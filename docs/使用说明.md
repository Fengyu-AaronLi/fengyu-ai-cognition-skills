# 使用说明

这份文档面向第一次接触这四个 Skill 的人。读完你应该知道：它们各自拦什么、什么时候会自己跳出来、装完第一句话该说什么，以及它们明确不做什么。

## 先搞清楚这不是什么

市面上大部分"Skill"是一段长提示词。你把它贴给模型，模型读完，然后**自觉**遵守。问题是自觉这件事没有着力点：模型说它查过了，你没有办法知道它到底有没有查。

这四个不一样。它们每个都带一个跑在你本机的小程序。模型负责判断（这句话算不算事实、这个标签底下是什么行为），程序负责那些不该指望自觉的部分：把你的原话冻住不许改写、把来源存成文件、没有存到证据就不许写"已确认"、中途崩了能接着跑、跑完能回放复查。

打个比方。提示词像是你跟人说"记账要老实"。这四个是给你装了一台收银机：钱进钱出都打小票，小票对不上，账就结不了。收银机不能让人变诚实，它只是让不诚实这件事留下痕迹。

所以有一句话得说在前面：**它们不保证 AI 说的是对的，也不消灭幻觉。** 它们只保证，当 AI 给你一个结论时，你能查到这个结论是踩着什么走到那一步的。

## 装之前的三个前提

1. **要有 Python 3.10 或更高版本。** 终端里跑 `python3 --version` 看一眼。核心功能只用标准库，不用装别的包。
2. **目前支持 macOS 和 Linux。** 状态锁用了 Unix 的 `fcntl`，原生 Windows 暂时不在支持范围（WSL 可以）。
3. **它们会往硬盘写东西。** 每次运行会建一个工作目录，把你的输入原文、抓到的来源、判断记录全存下来，而且不会自动清理。**这些目录默认按私密材料对待**，里面可能有你贴进去的聊天记录、姓名、链接。别顺手提交到公开仓库。

## 安装

四个 Skill 的安装脚本**名字不一样**，别照着一个改名套用。统一的做法是：先定一个安装目录，再按下表跑对应命令。

```bash
REPO_DIR=/path/to/fengyu-ai-cognition-skills
SKILL_ROOT="$PWD/.agents/skills"
```

| Skill | 安装命令（脚本在 `$REPO_DIR/skills/<名字>/scripts/` 下） |
|---|---|
| `auditing-ai-claims` | `python3 install.py --target-root "$SKILL_ROOT"` |
| `defining-problems-before-prompts` | `python3 package_skill.py --target-root "$SKILL_ROOT"` |
| `separating-facts-from-stories` | `python3 package_runtime.py --target-root "$SKILL_ROOT"` |
| `breaking-identity-labels` | `python3 build_package.py install --help` 先看参数，它是 `build / verify / install` 三个子命令 |

四个安装器有一个共同行为：**只复制白名单内的运行文件，不覆盖已存在的目标，不用符号链接。** 所以重装前要么换目录，要么先把旧的删掉。

装完验证一下。`auditing-ai-claims` 和 `defining-problems-before-prompts` 有 `doctor`，输出里 `ok: true` 就是通过：

```bash
python3 "$SKILL_ROOT/auditing-ai-claims/scripts/claim_audit.py" doctor
"$SKILL_ROOT/defining-problems-before-prompts/scripts/dpbp" doctor
```

`breaking-identity-labels` 用 manifest 逐文件核对哈希：

```bash
python3 "$SKILL_ROOT/breaking-identity-labels/scripts/build_package.py" verify --package "$SKILL_ROOT/breaking-identity-labels"
```

输出 `valid: true` 才算装完整。`separating-facts-from-stories` 用 `package_runtime.py --verify <已安装目录>`。

要注意一个区别：**装好了不等于 AI 会自己找到它。** 前者是文件到位，后者取决于你的 AI 客户端会不会扫描 `.agents/skills/` 这个目录。如果 AI 没有自动触发，直接在对话里点名调用就行，比如"用 auditing-ai-claims 审计下面这段"。

## 四个 Skill 分别拦什么

### 1. `auditing-ai-claims` · AI 主张审计

**拦的是**：AI 给你一个可以被外部核实的结论，但没有真的去核实。

**什么时候该出现**：涉及价格、法条、现任 CEO、论文结论、产品能力、公司数字、引语、日期、版本号。哪怕你没说"帮我核实"，只要句子里有这类东西就该触发。

**怎么用**：

```
用 auditing-ai-claims 审计下面这段 AI 回答。先给我简明主张账本，再保留可回放证据。

[粘贴 AI 回答]
```

**你会拿到什么**：一张表。每行一条被拆出来的原子主张，标着它现在是什么状态（已确认 / 部分支持 / 被反驳 / 无法核验 / 当前未知）、哪份证据支持到哪一步、还缺什么、下一步该查哪里。来源回执、原文引文、字符位置这些放在报告后面，需要复查时再往下翻。

**它的硬规矩**：没打开过来源，就不许写"来源证实"。一段证明"这篇论文确实存在"的引文，不能同时用来证明"论文的结论成立"。公司自己发的稿只能证明公司这么说过。查不到不算失败，老老实实停在"当前未知"才是正确结局。

**它不做**：纯翻译、润色、个人感受、价值判断、创意写作。这些里面没有事实句，它不该跳出来。

---

### 2. `breaking-identity-labels` · 身份标签拆解

**拦的是**：一个标签被当成了对你这个人的解释，然后开始预测你的能力和未来。

**什么时候该出现**：出现 MBTI、回避型依恋、高敏感、拖延症、讨好型人格这类词，并且被用来解释"我为什么会这样"或者"我以后会怎样"。也包括你让 AI 根据几段聊天记录推断你是什么型。

**怎么用**：直接把那句话说给它，比如"我是不是回避型人格，我一吵架就想跑"。

**你会拿到什么**：它先分诊，不是所有情况都往下拆。

| 分诊结果 | 它会做什么 |
|---|---|
| 有现实安全风险 | 停掉一切分析，先给现实中的求助方式 |
| 功能明显受损 | 建议现实里的专业评估，不给身份实验 |
| 你在转述正式诊断 | 保留你的原话，不替你扩写症状和结论 |
| 只是一个稳定偏好 | 确认边界就结束，不给你安排"纠正实验" |
| 信息不够 | 只问一个能改变判断的问题 |
| 确实适合拆解 | 走完整十项 |

走到完整十项时，你会看到：标签原文、这个标签是谁给的、底下具体是哪几个行为、发生在什么情境和频率、已知的反例、可能影响它的变量、目前判断不了的部分，以及一个小规模、可逆、有期限的现实实验。

**它的硬规矩**：不诊断，不确认也不撤销任何诊断。不拿一个正面标签替换负面标签（"你不是回避型，你是高敏感"这种一样不许）。不把停药、改药、辞职、分手写成"实验"。变量只能标成假设，不许写成事实。

---

### 3. `defining-problems-before-prompts` · 提问前定义问题

**拦的是**：问题还没定义清楚，答案已经生成完了。

**什么时候该出现**：建议类、优化类、规划类、以及高风险选择。"我该不该辞职""怎么用 AI 提高效率""帮我做个能赚钱的 App"都算。

**它的核心判断**是先分三条路：

- `execute`：这题已经说清楚了，直接干，不问你任何问题。翻译、格式转换、计算这类会走这条。
- `define`：缺的东西会改变结论，停下来把问题定义补齐。
- `defer_to_user`：涉及辞职、分手、医疗、法律、投钱。它把证据和代价摆清楚，但**不替你选**。

**怎么用**：

```bash
scripts/dpbp gate --offline < request-envelope.json
scripts/dpbp init < request-envelope.json
scripts/dpbp validate < problem-spec.json
scripts/dpbp render < problem-spec.json
```

**你会拿到什么**：一份十二项的问题说明书，包含现实结果、决定性未知、成功证据、失败条件，以及一个可逆的验证动作。

**最多问你三个问题**，这是写死的上限。另外有一条规矩挺重要：它自己提的验收标准只能算"待定"，必须你点头才作数，而且新标准得真的增加一个能观察的维度，不能只是把"变得更好"换个说法。

**它不做**：不给你万能提问公式，不做提示词润色，不替你拍板。

---

### 4. `separating-facts-from-stories` · 事实与故事分离

**拦的是**：有限的观察被讲成了确定的动机、诊断、人格和未来。

**什么时候该出现**：你在描述一件让你难受的事，中间混着"他肯定是""他就是""他以后也会"。也包括拿旧材料加新料继续推断。

**怎么用**：把整段材料保存成文件再启动，别直接拼进命令行。

```bash
python3 "$SKILL_DIR/scripts/workflow.py" start \
  --input "$INPUT_FILE" --workspace "$WORKSPACE" \
  --case-id "$CASE_ID" --mode auto
```

**你会拿到什么**：一份八栏的 casefile。核心是把你原话里能算"可观察事实"的句子挑出来，一个字都不改写，剩下的分别归到解释、动机推断、身份判断、预测。每一条都必须指回你原文里的确切位置。

有两个设计值得单独说：

- **不许释义借锚点。** 事实栏里的句子必须和你的原话逐字相同。改写一下再放进事实栏是被程序拒绝的。
- **拿不准的不硬塞。** 有些句子看着像在讲事件，但没通过事实语法，它会单独列成"待确认观察"，而不是替你决定算不算事实。

**它的硬规矩**：不诊断回避型、NPD、人格障碍。不判断爱不爱、有没有出轨、会不会复合。不替你决定分手、辞职、对抗。碰到即时风险，先给现实支持，不做分析。

## 什么时候它们不该出现

这一条和"什么时候该用"一样重要。四个 Skill 都写了明确的不触发边界：

- 纯翻译、纯格式转换、纯计算，直接执行，不许拦。
- 已经定义清楚的任务，`defining-problems` 会自己放行，不许多问一句。
- 只是个人感受或者隐喻，`auditing-ai-claims` 不该跳出来查证。
- 只是一个稳定偏好，`breaking-identity-labels` 不该安排实验。

如果你发现它在不该出现的地方拦你，那是 bug，欢迎提 issue。

## 隐私边界

- 运行目录里有你的原始输入、抓过的链接、判断记录。**默认当私密材料处理。**
- 本地哈希只能证明"存下来之后这些字节没被动过"。它不是可信时间戳，不是远程签名，也证明不了来源本身是真的。
- 工作区里的 HMAC 挡不住已经拿到你本机控制权的人。
- `events.jsonl` 是用来排查和恢复的日志，不是防篡改审计链。

别把真实私人聊天、可识别身份的信息、医疗法律材料、公司机密或者密钥放进要公开的样例里。
