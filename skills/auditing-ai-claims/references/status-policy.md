# Status and decision policy

## 三道门

1. `source_identity_gate`：来源身份、作者、版本和标识是否匹配
2. `content_support_gate`：正文是否直接支持该原子主张及其范围
3. `action_applicability_gate`：证据是否足以支持用户准备采取的行动

来源真实不等于引用正确，内容支持不等于个案行动适用。

三道门按各自证据用途判断。来源身份引文不能替代正文支持，正文支持不能替代当前性，研究设计标签也不能替代对结论范围的核对。

## 输入处置门

审计先冻结整段输入，再让每个输入单元落入且只落入一种处置：未审、被原子主张覆盖、明确排除。显式声明的 `declared` 候选必须在原文中只出现一次；声明区间只覆盖自身字符，所在句的剩余区间继续生成 `auto_gap`。运行时发现的 `auto_gap` 不等于事实，它表示这段文字尚未被审计者处理。

只有 `auto_gap` 可以排除。显式声明为事实候选的 `declared` 不能被重新归类为非事实。自动补漏中的观点、隐喻、创意写作、个人感受、指令、关系动机或其他明确非事实内容可以排除，且必须保存分类、具体理由和时间。不能因为主张难查、来源打不开、争议大或可能为假就排除；这些情况应进入主张账本，并用 `unverifiable` 或 `current_unknown` 保留未知。

一条原子主张只覆盖一个冻结候选，且主张文本必须是该候选中的精确连续子片段。一个复合候选可以拆成多条原子主张，直到最后一条主张关闭该候选。仍有未审单元、处置缺失、同一单元同时处于多种处置，或主张文本与候选没有精确绑定时，审计不能完成。

## 五种状态

| 状态 | 最低条件 |
|---|---|
| `confirmed` | 合格回执、可复现直接引文、身份与内容门通过、范围和日期匹配、无决定性冲突，并完成当前反证检查 |
| `partially_supported` | 来源支持较窄版本，原句含额外外推、条件缺失或范围扩大，并完成当前反证检查 |
| `refuted` | 可比的可靠来源提供已定位的直接冲突证据，并完成当前反证检查 |
| `unverifiable` | 来源缺失、打不开、标识无效或材料不足 |
| `current_unknown` | 事实会变化，当前性未建立或决定性证据尚不存在 |

没找到证据不等于被反驳。一个来源存在也不等于整句被确认。

`partially_supported` 不是隐藏冲突的容器。只要同一被审主张仍有已登记冲突或直接冲突证据，就必须拆出真正获得支持的窄主张，或维持未知；不能一边保留冲突，一边把原句整体标成部分支持。

三个决定性状态都必须先有用途为 `source_identity` 的直接精确证据，来源身份门才能通过。内容门只读取 `substantive`：

- `confirmed` 需要直接实体支持，内容门为 `pass`
- `partially_supported` 需要直接或部分实体支持，内容门为 `pass` 或 `partial`
- `refuted` 需要直接实体冲突，内容门为 `fail`，并明确记录冲突

`study_design`、`source_identity` 或 `currentness` 引文不能被内容门当成实体结论。所有直接、部分和冲突证据都必须保存非空支持范围、定位器和精确引文。

## 推断跨度

| 级别 | 含义 | 状态上限 |
|---|---|---|
| 0 | 原文直接陈述，范围一致 | 可考虑确认 |
| 1 | 透明计算或明确术语转换 | 展示转换与条件 |
| 2 | 跨人群、时间、任务、法域、版本或比较口径 | 至多部分支持 |
| 3 | 相关性变因果、benchmark 变全场景、自述变独立事实 | 不得写来源已证实 |

## 因果

研究只报告 `associated`、`predictive`、survey 或 self-reported 结果时，默认不能确认因果。因果确认必须记录能够识别因果的设计，例如随机试验、自然实验、可信准实验或具有识别策略的纵向研究。设计名称通过机器门不等于研究质量已经自动审查。

因果主张进入 `confirmed`、`partially_supported` 或 `refuted`，都必须连接一段用途为 `study_design` 的直接原文，明确指出能够承载该方向判断的设计，并填写合格 `causal_basis`。横截面、自报或相关性材料不能把字面因果主张升级为部分支持，也不能仅凭相关性冲突把因果主张判成被反驳。

## 高时效状态

高时效主张的 `as_of` 必须等于本次核验日。只把来源标成 `freshness_status: current` 或写一句当前性理由不够；凡进入 `confirmed`、`partially_supported` 或 `refuted`，都要另有用途为 `currentness` 的直接精确引文或已定位的日期记录，且推断跨度不超过 1。当前性未建立时只能停在 `current_unknown` 或 `unverifiable`。

## 客观性能

模型跑分、产品效果、准确率、速度和排名使用 `objective_performance`。公司页面、新闻稿、模型卡或主体自述可以确认“该主体声称了这个数字”，不能单独确认数字代表独立客观性能。若要审计声明本身，应改写成 `quotation_attribution`；若要审计性能本身，需匹配版本、任务、指标、样本、比较集、测试条件和独立来源。

## 高风险行动

医疗、法律、金融主张可以核验事实，但不能凭群体研究、一般法规摘要、公司宣传或模型回答直接放行个案行动。

高风险主张的行动门只能是 `professional_review` 或 `insufficient`。报告必须保留适用人群或法域、信息日期、版本、个案未知和专业边界。

## 判准

遇到“彻底解决、安全、最好、行业第一、广泛采用”等结论词，记录：对象、指标、范围、时间、成立条件和失败条件。没有共同判准时，先审计其中更窄的事实子句，将总括结论停在未知，不能擅自补一个数字阈值。

## 反证状态门

assessment 之后必须为每条主张保存一个绑定当前 basis 的 countercheck。记录至少包含：可改变状态的 falsifier、实际检查的活动来源、结果、停止理由、运行时生成的时间和 basis hash。

`confirmed`、`partially_supported` 和 `refuted` 至少要实际检查一个合格来源。`conflict_found` 必须已有绑定的 conflict 证据。`scope_narrowed` 表示主张或 assessment 需要改变，不能直接越过摘要门。`inconclusive` 是合法结果，尤其适用于无法核验和当前未知，但必须明确为什么本轮无法获得更有信息量的材料。

主张、evidence、assessment 或被检查来源的活动状态改变后，旧 countercheck 不再是当前记录。没有找到反证不能自动加强主张状态。

## 状态循环

`next` 是只读状态机，不替审计者生成结论。每次写入后重新读取：

```text
claim_extraction
→ claim_assessment
→ claim_countercheck
→ audit_summary
→ gate_repair 或 ready_to_finish
→ complete
```

任何新证据、重判、摘要变化或 bundle 变化都可能使后续状态失效并回到前一阶段。`gate_repair` 不是终止状态，错误被修复后继续调用 `next`。只有当前 gate 通过，当前报告绑定相同 bundle，阶段才是 `complete`。`not_triggered` 表示输入整体不属于外部事实审计，不表示内容被证明正确；该路由只由 `next` 返回，不生成审计报告。
