# 零门槛降级体验

这是给无法安装本地 Skill 的聊天工具使用的兼容提示词。它可以改善审计结构，但没有输入哈希、字符绑定、来源回执、PDF 解析记录、状态循环、并发锁、确定性 gate 或离线回放。

模型即使说“我打开了页面”，你也无法仅凭这份回答验证它是否真的留下了原始工件。因此，这个入口只能叫提示词辅助核验，不能冒充完整 `auditing-ai-claims` 工作台。

复制下面整段，把最后的占位内容换成要审计的 AI 回答：

```text
请审计下面这段 AI 回答。不要用你自己的记忆给它投票，也不要因为它有链接、数字、DOI、正式语气或参考文献格式就默认可信。

只审计原则上可由外部证据核验的陈述，例如论文、产品能力、公司数据、政策、价格、人物身份、职位、日期、版本、引语和当前事实。个人感受、关系动机、价值判断、隐喻和创意写作不作为事实审计对象。混合文本只审事实部分。

先对整段输入做覆盖检查。把每个有意义的片段放入且只放入一种处置：
1. 事实候选，进入主张账本
2. 明确非事实，写出分类和具体排除理由
3. 暂未处理，明确列出，不能静默省略

对事实候选执行：
1. 拆成原子主张。论文存在、作者匹配、DOI 归属、实验结果和普遍结论必须分开。
2. 标记主张类型、时效性和核验日期。价格、法律、职位、当前能力以及“现在、最新、最便宜”属于高时效。
3. 对“彻底解决、安全、行业第一、广泛采用、最新、最便宜”等词，写清对象、指标、范围、时间、成立条件和失败条件。缺少定义时不要私自补阈值。
4. 优先实际打开官方原始文件、论文全文、监管文件、财报、代码或实际测试。搜索摘要只能帮助找到页面，不能作为核心证据。若不能联网、页面打不开或 PDF 正文无法读取，写“未打开”或“正文不可用”，不能写“来源证实”。
5. 为每段原文只标一个证据用途：
   - 来源身份：作者、DOI、文件或版本是否匹配
   - 实质支持：正文是否支持或冲突于主张内容
   - 研究设计：设计是否能承载因果推断
   - 当前性：日期、版本和页面状态能否代表核验日
   不得让一段来源身份引文同时证明研究结果。
6. 检查对象、版本、日期、人群、任务、法域、指标、比较集和条件。公司页面可以证明公司这样说过，不等于独立验证客观性能。
7. 区分相关性与因果性。自报调查或相关性研究不能把“AI 导致人变笨”写成已证明或部分证明。一个 benchmark 也不能代表现实中的所有回答。
8. 每条只用五种状态：已确认、部分支持、被反驳、无法核验、当前未知。找不到证据不等于被反驳。
9. 在定下状态后做一次反证检查：写出什么证据会改变当前状态、实际检查了哪些已经打开的来源、发现了冲突还是没有结论、为什么本轮停止。没有找到反证不等于已证明；发现范围需要缩窄时先改主张再判断。
10. 每条都写当前未知、置信理由和最有效的下一步。不能生成缺失的作者、DOI、数字或看起来合理的引用。
11. 医疗、法律、金融内容只缩小事实争议，不替代专业个案判断。不保证答案绝对正确。

先输出普通人可读的简明首屏：

核验日期：
快速结论：

| ID | 原子主张 | 状态 | 关键理由 | 当前未知 | 下一步 |
|---|---|---|---|---|---|

然后输出复核附录：

1. 输入处置表：原文片段、事实候选或排除类别、排除理由、是否仍待处理
2. 来源表：来源、层级、日期、是否实际打开、证据用途、精确支持范围、冲突
3. 反证表：主张 ID、可推翻条件、实际检查来源、结果、停止理由
4. 边界：这次核验不能证明什么
5. 全局下一步：只选信息增益最高的一项，并说明它会改变哪些主张

若你无法实际打开任何来源，也要完成表格，但支持性状态只能是无法核验或当前未知。不要为了让报告看起来完整而补一个确定答案。

要审计的 AI 回答：
[粘贴在这里]
```

如果需要来源回执、精确子片段绑定、失败恢复、PDF fail-closed 和可回放 gate，请安装完整 Skill。当前完整 Skill 仍是 NO-GO 的本地候选，尚未完成新鲜行为与自动发现验收。
