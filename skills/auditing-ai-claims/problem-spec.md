# Problem Spec：AI 主张审计工作台

## 1. 用户真正面对的问题

AI 回答可以同时拥有流畅语言、具体数字、正式引用和确定语气，却仍然包含不存在的来源、过期事实、证据范围错配或没有说出口的推断。

危险不只是“模型会说错”。更具体的问题是：用户很难从成品外观判断它是否真的完成了研究。一个链接可能没有打开，一段真实论文可能没有支持那句话，一个公司页面可能只证明公司自己这样说过，一个旧页面可能无法回答“现在”。

因此，本 Skill 不让另一个 AI 再投一次真假票。它把一次核验变成可恢复、可检查、可停止的工作流：冻结整段输入，拆出原子主张，保存来源和精确引文，隔离证据用途，强制反证检查，执行硬门，保留未知，再给出最高信息增益的下一步。

项目的警示性命题是：

> AI 越像一份正式研究报告，用户越需要检查它有没有真的完成研究。

这是产品判断，不冒充“引用越多必然导致误信”的已证因果结论。

## 2. 产品不是提示词，而是受控循环

完整产品必须实际调用本地运行时，并由 `next` 导航状态：

```text
start
  ↓
next
  ├─ claim_extraction
  ├─ claim_assessment
  ├─ claim_countercheck
  ├─ audit_summary
  ├─ gate_repair
  ├─ ready_to_finish
  └─ complete / not_triggered
```

每轮只解决当前最明确的缺口：

1. 输入有没有遗漏
2. 候选有没有拆成可判定的主张
3. 来源有没有实际打开
4. 引文负责证明什么
5. 状态有没有越过证据范围
6. 什么反证会改变状态，实际检查了什么
7. gate 还拦截什么
8. 报告是否与当前 bundle 绑定

每次写操作、抓取失败或 gate FAIL 后，Agent 都重新调用 `next`。它不能凭聊天记忆猜进度，也不能因为来源找不到就无限搜索。合格终点包括诚实的 `unverifiable` 和 `current_unknown`，不只包括确认或反驳。

## 3. 范围

### 处理

- 产品能力、参数、价格、发布日期和当前可用性
- 论文存在性、作者、DOI、研究设计、样本和研究结论
- 公司数据、财报数字、采用率、市场排名和公司身份
- 法律、政策、监管决定、适用法域和生效时间
- 人物身份、职位和其他会变化的公共事实
- 引语归属、来源是否存在、来源是否真的支持该句
- 从上述事实推出的比较、概括、因果和行动结论

### 不处理

- 他人的关系动机、爱不爱、是否试探等读心问题
- 用户的感受是否真实
- 明确标注的观点、价值判断、隐喻和创意写作
- 纯审美判断和不以外部事实为前提的个人偏好

混合文本只审计其中原则上可核验的外部事实，但不能静默丢掉其余文本。非事实片段也要保存分类和具体排除理由。关系动机和个人叙事属于 `separating-facts-from-stories` 的范围。

## 4. 整段输入覆盖

仅让模型列出“关键主张”仍会留下一个结构性漏洞：模型可以只挑容易核验的句子，再对剩余内容保持沉默。

V3.1 先保存未经改写的 `input.txt`。Agent 通过 `--candidates-file` 提交的候选事实子句必须与原文精确匹配，运行时为每项冻结：

- 稳定候选编号
- 原文精确子串
- 来源类别 `declared` 或 `auto_gap`
- UTF-8 文本 SHA-256
- 原文中所有字符区间

运行时同时切分未被声明候选触及的其余输入，标为 `auto_gap`。每个冻结单元必须且只能落入三种处置之一：

1. 待处理，阻止完成
2. 被一条或多条原子主张覆盖
3. 被明确归类为非事实内容，并保存非空理由与时间

账本复验会重新读取 `input.txt`，重算文本、哈希和字符区间。清空待处理列表、手改候选文字或把一个片段同时覆盖和排除，都不能完成审计。

## 5. 原子主张

原子主张是可以单独改变证据状态的最小陈述。下面这些命题不能挤在同一格里：

- 论文存在
- 作者与题名匹配
- DOI 指向该论文
- 某模型在某套测试中报告某个数字
- 该数字意味着现实中所有回答都没有幻觉

一条原子主张只能覆盖一个冻结候选。一个复合候选可以拆成多条原子主张，早期拆分保持候选开放，最后一条再关闭覆盖。这样允许细拆，但不允许用一条宽泛主张吞掉多个无关候选。

每条主张至少需要：

- 原子陈述
- 主张类型
- 时效性与核验日期
- 成立条件
- 失败条件
- 输入候选绑定
- 来源与证据连接
- 当前状态
- 置信理由
- 当前未知
- 下一步核验动作
- 绑定当前 assessment 的反证检查记录

## 6. 主张类型

| 类型 | 典型问题 |
|---|---|
| 存在与身份 | 论文、人物、机构、职位、产品是否存在并相符 |
| 数字与比较 | 价格、比例、样本量、排名、增长与“最便宜” |
| 产品能力 | 特定版本在特定设置下能否完成任务 |
| 客观性能 | 跑分、准确率、速度、效果、排名是否由独立材料或可复现实测支持 |
| 研究发现 | 论文实际观察、测量或报告了什么 |
| 因果主张 | A 是否导致 B，而不只是相关或可预测 |
| 法律与政策 | 法域、版本、生效日、对象、条件与例外 |
| 引语与归属 | 谁在何处说了什么，是否为原话 |
| 预测与承诺 | 尚未发生的结果，当前只能记为预测或主体承诺 |

若一句话同时含事实和观点，只拆事实部分，观点部分进入明确排除记录。

## 7. 来源层级与证据角色

来源层级表示离原始记录有多近，不表示它自动为真。

| 层级 | 典型来源 | 最窄可支持范围 |
|---|---|---|
| A1 | 法规、监管文件、论文全文、财报、官方数据、代码、可复现实测 | 原始记录或测试在限定条件下写了什么 |
| A2 | 公司产品页、新闻稿、模型卡、管理层陈述 | 该主体作出了什么自述 |
| B | 有方法和出处的专业二手分析 | 对原始材料的专业解读或复核 |
| C | 普通媒体、社交媒体和未给原文的转述 | 搜索线索 |
| D | 另一个 AI 回答或无出处摘要 | 待查输入，不是证据 |

每条来源还要标记证据角色，例如原始记录、主体自述、独立复现、监管记录、专业分析、二手报道或线索。

公司可以权威说明自己的公开价格、条款和声明，但公司自测不能单独证明客观性能、行业排名或独立有效性。多个页面若转述同一个根来源，仍然只算一个证据根。

## 8. 一条引文只能承担一个用途

真实来源不等于支持当前句子。为了阻止“一份文档包办所有证明”，每条证据连接还要记录 `evidence_purpose`：

| 用途 | 负责回答的问题 | 不能偷渡的结论 |
|---|---|---|
| `source_identity` | 来源、作者、DOI、文件或版本是否匹配 | 研究结果因此成立 |
| `substantive` | 正文是否支持或冲突于主张内容 | 研究设计因此能证明因果 |
| `study_design` | 原文明确写了什么研究设计 | 结果因此必然显著或可普遍外推 |
| `currentness` | 日期、版本和页面状态能否代表核验日 | 历史材料因此仍是当前状态 |

同一来源可以建立多个证据连接，但每次只能绑定一个用途及其对应的精确引文、最窄支持范围和推断跨度。用途标签不是强度标签，不能把上下文材料升级成直接证据。

## 9. 支持范围与推断跨度

比较来源和主张时至少检查：对象、版本、时间、人群、任务、法域、指标、比较集和条件。

| 推断跨度 | 含义 | 默认处理 |
|---|---|---|
| 0 | 原文与主张对象、范围和措辞一致 | 可以考虑已确认 |
| 1 | 只需透明计算或明确术语转换 | 展示转换并保留条件 |
| 2 | 跨时间、人群、任务、法域、版本或比较口径 | 通常只能部分支持 |
| 3 | 从相关到因果、从 benchmark 到现实全场景、从公司自述到独立事实 | 不得写成来源已证实 |

相关性或自报研究不能让原本的因果句以“部分支持”过门。正确处理是另建一个更窄的相关性主张，原因果主张保持未知。因果主张进入确认或部分支持时，还必须同时拥有允许的设计类别与 `study_design` 的直接精确引文。

## 10. 五种状态

| 状态 | 判定 |
|---|---|
| 已确认 | 已打开合格来源，身份、内容、日期和范围匹配，没有足以推翻的冲突，并完成绑定当前 assessment 的反证检查 |
| 部分支持 | 来源支持一个更窄版本，原句仍含范围扩大或额外推断，没有被隐藏的决定性冲突，并完成当前反证检查 |
| 被反驳 | 已打开的可靠来源与主张直接冲突，对象、条件和时间可比，并完成当前反证检查 |
| 无法核验 | 来源打不开、身份未建立、正文不可用或现有材料不足 |
| 当前未知 | 问题会变化，核验日的决定性证据尚未建立或尚不存在 |

找不到证据不等于主张为假。页面 404 不等于对象永久不存在。PDF 无法提取文本不等于正文已被检查。

每条状态都必须写非空的当前未知、置信理由和下一步。即使确实没有剩余未知，也要明确记录“无”，不能借空字段沿用旧结论。

## 11. 失败恢复与收敛

工作流必须保留失败，而不是把失败当成需要清理的脏数据：

- 抓取失败留下不可支持回执
- 来源写入每个阶段都写事务日志；中断后以同一 ID 和相同元数据幂等恢复。若原响应已无法复现，用 `aborted` 终态保留快照和原因，并永久封存该 ID
- 未连接主张的失败来源可以带理由退休，但回执和工件不删除
- 已连接来源不能靠退休绕过冲突
- 精确引文找不到时缩窄支持范围，不能补写句子
- gate 报输入或工件变化时重新取证，不能手改哈希
- 最高价值来源不可得时，保留未知并给出下一步，而不是无限搜索

一次运行只有三个诚实终点：

1. `complete=true`，所有输入有去向，主张已判断且完成当前反证检查，未知和下一步已冻结，当前 gate 与报告绑定
2. `not_triggered`，输入确实没有可核验外部事实
3. 基础设施阻断，明确写审计未执行或当前无法完成取证，不输出确认性判词

证据不足本身不是基础设施阻断。

## 12. PDF、动态页面与导入材料

运行时对 PDF 采用可选本地 `pdftotext` 适配器。只有解析器路径和版本可记录、固定参数执行成功、输出未超时且文本非空时，PDF 才能绑定精确引文。

解析器缺失、版本无法识别、PDF 损坏、超时、输出为空或超限时，系统 fail closed。原始 PDF 和失败原因可以留在证据轨迹中，但不能进入确认、部分支持或反驳的硬门。

动态 HTML 若无法由受控抓取获得正文，同样停在未知。外部浏览器或用户提供的 `capture` 只属于 caller-attested 导入，不能凭文件自身证明 URL 与内容绑定，因此只能作为上下文或待补材料。

网络抓取必须有覆盖全部重定向和正文读取的单一总时限，并有调用方不能抬高的跳转次数与字节硬上限，避免慢速持续响应让审计无限悬挂。

## 13. 并发、完整性与信任边界

- 既有工作区的只读命令使用共享文件锁，写命令使用排他锁，避免两个进程同时覆盖账本
- 文件锁只协调本机 CLI 进程，不是分布式锁，也不能防止绕过 CLI 直接改文件
- gate 绑定当前输入、账本、attestation、来源事务、回执和工件 bundle；任一变化都会让旧 gate 与报告失效
- 已渲染报告或 gate 被改时，`status`、`render` 和 `replay` 会把状态标为失效或拒绝继续
- 运行时抓取回执必须通过工作区 HMAC attestation，阻止只手写格式正确的回执冒充运行时抓取
- 本地 HMAC 和哈希只证明当前工作区内的记录一致性，不证明来源真实性，也不是可信时间戳；密钥泄露或本机失陷不在其防护范围内
- `events.jsonl` 是运行日志，不是防篡改审计链
- `replay` 只复验保存的历史观察，不刷新时效事实

## 14. 普通用户输出契约

报告第一屏应短而可行动：

| ID | 原子主张 | 状态 | 关键理由 | 当前未知 | 下一步 |
|---|---|---|---|---|---|

技术部分再保留：

- 候选输入绑定与排除项
- 主张类型、时效性和判准
- 来源层级、证据角色、日期和当前性
- 精确引文、字符选择器和证据用途
- 支持范围、推断跨度、冲突与三道门
- falsifier、实查来源、反证结果、停止理由与 basis hash
- 失败来源、获取资格和解析状态
- gate 警告、跨主张未知和全局下一步

产品目标不是让用户看更多字段，而是让用户先知道哪条能用、哪条不能用、为什么，以及现在做什么最划算。

## 15. 成功标准

一次合格审计必须做到：

1. 冻结整段原始输入并建立可重放的候选清单
2. 让每个输入单元处于待处理、主张覆盖或明确排除三种状态之一
3. 拆出影响结论或行动的关键原子主张
4. 精确绑定原文子片段，防止改写后漂移
5. 标记主张类型、时效性、成立条件和失败条件
6. 找到并实际打开一手来源，或承认没有找到
7. 检查来源是否直接支持该句，而不是只看标题和摘要
8. 隔离来源身份、实质支持、研究设计和当前性用途
9. 记录日期、版本、法域、对象、指标与支持范围
10. 区分相关性、预测性和因果性
11. 区分公司自述与独立证据
12. 明确冲突、当前未知、置信理由和最高信息增益下一步
13. 为每条当前 assessment 记录可改变状态的 falsifier、实查来源、结果和停止理由
14. 让来源提交中断可幂等恢复，且不删除失败轨迹
15. 让当前 PASS gate、报告和证据 bundle 可离线回放
16. 普通用户第一屏不被工程字段淹没

## 16. 红色阶段与真实风险

在候选 Skill 创建前，四个隔离 baseline 观察到：

- 伪论文案例没有补写样本量，却仍把未核验作者、题名和无效 DOI 排成正式参考文献，并给出可用于交稿的句子
- 调查案例拒绝“AI 会让人变笨”，但在替代句中删掉了自报、样本和知识工作者边界
- 当前价格案例直接给出模型名和价格，没有来源、比较口径或核验日期
- 隐喻案例正确没有进入事实账本

原始输出保存在 `evals/baseline/raw/`。它们是无 Skill 行为证据，不是当前工作台的行为通过证据。

V3.1 的工程 RED 还覆盖整段输入遗漏、候选漂移、安全文件协议、证据用途混用、PDF 解析失败、抓取总时限、来源事务崩溃恢复、回执认证、反证记录失效、并发写入和状态收敛等可执行缺口。具体证据与当前回归结果以 `evals/results.md` 为准。

## 17. 外部依据与边界

- [OpenAI 官方说明](https://openai.com/index/why-language-models-hallucinate/)及其[原始预印本](https://arxiv.org/abs/2509.04664)说明先进模型仍会生成看似合理但错误的陈述，评测激励也可能鼓励猜测。它不能证明任何产品已经消灭幻觉，也不能证明引用会导致误信。
- [NIST AI RMF 页面](https://www.nist.gov/itl/ai-risk-management-framework)与 [AI RMF 1.0 PDF](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf)支持按具体使用情境记录方法、不确定性、外部有效性和独立审查。它是自愿风险框架，不是产品认证。
- [Microsoft Research 页面](https://www.microsoft.com/en-us/research/publication/the-impact-of-generative-ai-on-critical-thinking-self-reported-reductions-in-cognitive-effort-and-confidence-effects-from-a-survey-of-knowledge-workers/)及其 [CHI 2025 论文 PDF](https://www.microsoft.com/en-us/research/wp-content/uploads/2025/01/lee_2025_ai_critical_thinking_survey.pdf)报告特定知识工作者样本和自报实例中的相关性。它不能证明 AI 导致人变笨或造成长期客观能力下降。

三份材料共同支持“有搜索、有引用、有透明说明不等于当前主张已经被证实”。它们没有直接证明“引用越多，用户越容易误信”的普遍因果效应。

## 18. 当前发行门

下列项目没有全部完成前，状态保持 `NO-GO / local candidate`：

- 新鲜会话中的完整行为复测
- 语义盲评和独立来源复核
- 安装后正向自动发现的真实工具轨迹
- 纯观点、隐喻和创意文本的负向不触发轨迹
- 干净环境安装与普通用户首屏验收
- 时效性示例的发行前重新核验

工程测试通过只能证明当前可执行契约，没有证明 Agent 在看不到开发上下文的新鲜会话里会正确拆主张、找来源、触发或不触发。当前没有公开、没有 push，也不声称已经开源。

## 19. 不保证什么
