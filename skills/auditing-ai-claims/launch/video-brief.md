# 视频骨架：AI 越像研究报告，你越要查

## 内容边界

这是演示骨架，不是完整逐字稿。

视频核心命题：

> AI 越会搜索、越会引用，你越容易把“像研究报告”误认为“已经被证明”。

更稳妥的落点：

> AI 越像研究报告，你越要检查它有没有真的完成研究。

前一句是视频的警示性命题，不冒充已经由实验直接证明的普遍因果。视频不得使用“消灭幻觉”“保证正确”“一键事实核查”等承诺。

## 唯一主案例

直接使用 C01 的真实 baseline，不另写一个更戏剧化的假回答。

原始输出：[`../evals/baseline/raw/C01-fabricated-paper.md`](../evals/baseline/raw/C01-fabricated-paper.md)

测试输入中的论文、作者、Atlas-3 和 DOI 是项目故意构造的评测夹具。模型输出是真实保存的无 Skill 回答。它先提醒不要编造，却继续把未核验的题名、作者和 DOI 排成正式参考文献，并给出可用于交稿的表述。

演示账本：[`../examples/demo.md`](../examples/demo.md)

V3.1 的新鲜行为复测与自动发现尚未运行。本视频可以展示 baseline 和工作台机制，不能把演示账本说成“新鲜会话已经通过”。

## 观众需要看懂的反差

| 看起来像 | 实际需要检查 |
|---|---|
| 有 DOI | resolver 是否能打开，是否指向这篇论文 |
| 有三名作者 | 作者、题名、年份和出版社记录是否匹配 |
| 有 0.0% | 指标、题集、题量、弃答率和评分方法是什么 |
| 有官方链接 | 原文到底支持来源身份、研究结果、研究设计还是当前性 |
| gate PASS | 记录满足审计契约，不是程序证明现实绝对正确 |

## 画面顺序

### 1. 一个听起来极专业的错误回答

- 先放原始 baseline，不先解释幻觉原理
- 视觉放大三名作者、英文论文名、12 个测试、0.0% 和 DOI
- 再放大“可直接用于交稿”
- 反转不是“AI 又胡说了”，而是“它把用户给的假前提加工成了更可信的成品”

### 2. 普通人为什么会信

- 链接让人误以为页面已经打开
- 精确数字让人误以为指标和比较范围已经确认
- 先谨慎提醒，再交付正式成品，会让成品更像审慎核验后的结论
- 引用格式降低了用户自己点击、定位和比对原文的冲动

这里只描述可观察的说服机制，不声称已有研究证明所有观众都会因此误信。

### 3. 先展示普通人第一屏

镜头先出现六列简明账本：

```text
ID｜原子主张｜状态｜关键理由｜当前未知｜下一步
```

观众先看到结果：论文、作者、DOI、测试结果和“彻底解决”不是一个真假按钮，而是五条证据状态不同的主张。

不要先用十几列技术表把普通观众挡在门外。来源回执、字符选择器、证据用途和三道门随后作为“为什么这张表值得复核”的后台证据出现。

### 4. 用工作流证明它不是提示词

屏幕展示真实状态循环：

```text
start
  → next: claim_extraction
  → next: claim_assessment
  → next: claim_countercheck
  → next: audit_summary
  → next: gate_repair 或 ready_to_finish
  → finish
  → next: complete
  → replay
```

每次写入或失败后重新调用 `next`。镜头显示 `cli_subcommand`、`required_inputs` 与稳定对象 ID，候选原文只作为数据写入 JSON 文件。重点不是背命令，而是让观众看到系统每次只要求一个明确动作，直到所有输入都有去向。

### 5. 展示整段输入三分法

- `start --candidates-file` 冻结完整原回答
- 声明候选保存原文精确子串、字符位置和哈希
- 未触及文本自动成为 `auto_gap`
- 每个片段只能待处理、被主张覆盖或带理由排除
- 难查和打不开不是排除理由

可以故意少声明一个句子，让 `next` 返回 `classify_candidate`。再把一个纯过渡句明确排除，同时把“彻底解决幻觉”登记为事实主张。这个画面最直接地证明系统不会只查模型自己挑中的部分。

### 6. 拆开同一句里的五个问题

1. 论文存在吗
2. 作者、题名、年份和 DOI 相符吗
3. Atlas-3 存在吗
4. 12 个测试和 0.0% 是什么指标与条件
5. 特定评测能否外推到现实全部回答

复合候选拆分时，画面展示多个 `claim --file` 输入都精确绑定同一个候选，说明同一句可以拆成多条主张，但一条主张不能吞掉多个无关候选。

### 7. 哪条来源看似存在，实际不支持

- 打开 DOI resolver 的保存记录，显示 2026-08-05 为 HTTP 404
- 正确结论不是“论文永久不存在”
- 正确结论是“这个 DOI 在核验日没有解析成功，论文身份当前没有建立”
- 搜索摘要和无匹配结果都不能替代出版社页或论文原文

随后展示证据用途隔离：

- DOI 结果只处理 `source_identity`
- 论文结果段才可能处理 `substantive`
- 方法段处理 `study_design`
- 核验日版本处理 `currentness`

让一个身份引文尝试冒充结果证据，再展示 gate 拒绝。这个画面比“请注意来源范围”更能表现 Skill 的工程价值。

### 8. 展示 PDF fail-closed

若演示来源是 PDF：

- 显示原始 PDF 工件已保存
- 显示本机 `pdftotext` 路径和版本被记录
- 成功时再展示可复现文本与精确引文
- 失败时展示支持资格关闭，而不是让 Agent 凭摘要继续写结论

视频不需要故意破坏真实论文。可以用项目自有的无敏感 fixture 演示“解析器缺失或损坏 PDF 时不能绑定正文”。不得把 `capture` 的外部导入说成已验证原文。

### 9. 展示反证状态，而不是免责声明

- assessment 后 `next` 必须进入 `claim_countercheck`
- 展示“什么证据会改变当前状态”
- 展示实际检查的来源、结果与停止理由
- 改动主张或证据后，旧 countercheck 因 basis hash 不匹配而失效
- 没找到冲突不等于自动确认

这个画面回答“它为什么不只是更长的提示词”：反证动作是运行时强制阶段，不能靠一行“仍需核实”跳过。

### 10. 展示失败来源如何恢复

- 一次失败抓取留下不可支持回执
- 在工件、回执或账本之间模拟中断，事务状态停在未完成阶段
- 用相同 source ID 和元数据重试，运行时幂等恢复到 `committed`
- 若原响应已经无法复现，展示 `abort-source-transaction` 保留 journal 和理由，并永久封存该 source ID
- `next` 在 gate 修复阶段列出可恢复来源
- 未连接主张时，用 `retire-source` 写入具体理由
- 换新 source ID 查询正式镜像
- 原失败回执仍在技术报告中

这说明恢复不是删除失败，也不是覆盖旧文件。已经连接主张的来源不能靠退休绕过冲突。

### 11. 哪部分最终仍然未知

- 是否有题名不同的相近研究
- 是否有未公开或内部的 Atlas-3
- 是否有模型在某个限定测试里得到零次观测错误
- 回答是全部构造、转述错误，还是标识写错
- 限定结果能否外推到现实任务和未来版本

停在未知不是失败。工作台允许 unknown 报告通过，是为了阻止审计者再造一轮幻觉。

### 12. 观众可以立刻执行的动作

先做一件事：点击最核心的引用，打开原文，找到它真正负责的那一段。

如果还能多做三步：

1. 看发布日期和版本
2. 对照对象、指标、任务和比较范围
3. 区分主体自述与独立复现

若原文打不开，正确动作不是让 AI 补一条引用，而是把结论降为无法核验或当前未知。

## 适用边界

- 适用：论文、产品、公司、政策、价格、人物身份和其他外部可核验主张
- 不适用：关系动机、个人感受、纯价值判断、隐喻和创意表达
- 混合文本：只审事实片段，但其他片段必须被明确分类，不得静默遗漏
- 医疗、法律、金融：只能缩小事实争议，不能替代个案专业判断
- 动态页面、付费墙和无法解析的 PDF：可以留下失败记录，不能装作已经读过正文

## 钩子方向

首选：

> 这是一个 AI 生成的假论文。最危险的不是它编了，而是它先提醒你别编，然后替你排成了正式引用。

备选方向：

- 有 DOI，不等于有论文
- AI 最像研究报告的时候，最值得你检查
- 它没有核验，只是把你的假前提排版得更像真的

## 标题方向

- AI像论文，不等于有证据
- 有引用，也可能没核验
- AI越专业，你越要查

封面方向：

```text
越专业
越要查
```

## 收尾动作

让观众把一段 AI 回答粘贴给已安装本 Skill 的 Agent，先拿到简明主张账本，再按需要展开技术证据。不能安装时可以使用 `zero-threshold-prompt.md`，但要明确它没有运行时回执与回放能力。

结尾只承诺一件事：这个 Skill 会逼审计过程把证据能走到哪里、走不到哪里说清楚。它不保证绝对正确，也不消灭幻觉。

## 拍摄前发行门

- 使用独立、无敏感信息的演示工作区
- 重新核验视频里出现的时效性页面和访问日期
- 不展示用户真实输入、查询参数、私有路径或证据正文
- 不说“已公开”“已开源”“已发布”
- 不说新鲜行为、语义盲评或自动发现已经通过
- 若行为与自动发现仍未完成，画面明确标注 `NO-GO / local candidate`
