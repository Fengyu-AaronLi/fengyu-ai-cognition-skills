# auditing-ai-claims V1 README（归档）

`auditing-ai-claims` 把一段像研究报告的 AI 回答拆成可检查的原子主张，再逐条核对来源、日期、证据范围、推断跨度和未知。

它不让另一个 AI 再投一次票，也不承诺消灭幻觉。

## 30 秒体验

最简单的用法不需要安装：打开 [`zero-threshold-prompt.md`](../zero-threshold-prompt.md)，复制整段提示词，把最后的占位文字换成你要检查的 AI 回答。

也可以在已经安装本 Skill 的 Agent 中直接输入：

```text
审计下面这段 AI 回答。请拆出最影响结论或行动的原子主张，实际打开原始来源，并给我简明主张账本：

[粘贴 AI 回答]
```

你会得到类似这样的结果：

| 原子主张 | 来源状态 | 支持范围 | 状态 | 下一步 |
|---|---|---|---|---|
| 某 DOI 对应指定论文 | DOI 当日无法解析，未找到论文原页 | 不能据此断言论文永久不存在 | 无法核验 | 向提供者索取 PDF 或出版社记录 |
| 某 benchmark 报告 0% 错误 | 未找到原始评测 | 模型版本、题集、指标和设置均未知 | 无法核验 | 打开论文方法与结果章节 |
| 幻觉已经彻底解决 | 已打开的一手材料仍明确讨论现存幻觉 | 不能从单一评测外推到现实全部回答 | 被反驳 | 改写为限定版本并补现实评测 |

完整演示见 [`examples/demo.md`](../examples/demo.md)。

## 什么时候会触发

适合检查：

- 论文、作者、DOI 和研究结论
- 产品能力、价格、排名和当前可用性
- 公司数据、财报数字和公司宣传
- 法律、政策、监管决定和人物职位
- 引语、引用、具体数字和其他外部可核验事实

不适合检查：

- 他人的内心动机
- 用户自己的感受
- 价值偏好、隐喻和创意写作
- 不依赖外部事实的审美判断

混合文本只审计可核验子句。关系动机应交给 `separating-facts-from-stories`。

## 安装

项目级安装，把 Skill 复制到目标项目的 `.agents/skills/`：

```bash
mkdir -p .agents/skills
cp -R /path/to/fengyu-ai-cognition-skills/skills/auditing-ai-claims .agents/skills/auditing-ai-claims
```

用户级安装可复制到 Agent 实际支持的用户 Skill 目录。不同客户端的目录和发现规则可能不同，先以客户端文档为准，不要把“文件复制成功”写成“Skill 已触发”。

安装后必须新开干净会话，分别测试：

```text
请审计这段 AI 回答里的论文、DOI 和结论。
```

```text
这是一段个人隐喻，请只评估语言，不做事实核查。
```

第一条应加载本 Skill，第二条不应加载。当前候选包的清洁会话记录与边界见 [`evals/results.md`](../evals/results.md)。

当前实测并未完全达到第二条：C04 在自动发现层仍读取了 Skill，但执行层正确识别为隐喻，没有生成事实账本。正向自动发现已成功，完整 CLI 回答则被网络传输故障中断。因此本候选的行为边界可以复测，自动路由门仍未通过。

## 输出是什么

默认输出简明主张账本。每条至少记录：

- 原子主张、主张类型、时效性
- 原始来源、来源层级、来源日期、是否实际打开
- 是否直接支持、真正支持的范围、推断跨度
- 反证或冲突
- 已确认、部分支持、被反驳、无法核验或当前未知
- 置信理由和信息增益最高的下一步核验动作

“已确认”必须有实际打开的一手来源。搜索摘要、普通媒体和另一个 AI 回答不能替代原文。

## 边界

- 找不到来源不等于主张为假
- DOI 当日 404 不等于论文永久不存在
- 公司自述可以证明“公司这样说过”，不能自动证明性能被独立验证
- benchmark 改进不能直接外推到现实中所有法律、医疗或金融回答
- 当前价格、法律、职位和产品能力必须写核验日期
- 医疗、法律和金融结论保留法域、个案和专业边界
- 本 Skill 不保证审计绝对正确，也不声称消灭幻觉
