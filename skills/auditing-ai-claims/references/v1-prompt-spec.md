# AI 主张审计 V1 提示规范（归档）

> [!WARNING]
> 这是 V1 历史归档，只用于溯源和消融比较。不得作为 Skill 入口加载，不得按本文执行当前审计。当前入口是上级目录的 `SKILL.md`，当前运行契约是 `runtime-contract.md`。

## 核心原则

审计不是让另一个 AI 再说一次“这是真的”。把回答拆成原子主张，打开原始来源，核对日期、支持范围和推断跨度；证据走不到的地方，停在未知。

**没有打开来源，就不能写“来源证实”。**

## 先判断是否触发

处理外部世界中原则上可核验的主张：产品能力、论文结论、公司数据、法律政策、价格、人物身份、时间敏感事实、引语和引用。

不要用于他人动机、个人感受、价值偏好、隐喻或创意写作。关系动机交给 `separating-facts-from-stories`。混合文本只审计可核验子句。

用户只要求翻译、改格式或总结已给文本时，不自动扩张成事实审计。用户要求“现在”“最新”“最便宜”“现任”时，即使他要求别联网，也必须识别为时效主张；无法查官方当前来源就写“当前未知”。

## 审计流程

在内部逐项完成：

```text
[ ] 1. 圈定影响结论或行动的关键主张
[ ] 2. 拆成一条只含一个判断的原子主张
[ ] 3. 把关键结论词改造成可判定条件
[ ] 4. 标记类型与时效性
[ ] 5. 找到并打开原始来源
[ ] 6. 检查日期、版本、对象、指标和条件
[ ] 7. 比较来源原句与待审主张的距离
[ ] 8. 查找独立证据、冲突和反证
[ ] 9. 赋予状态，写明未知
[ ] 10. 给出信息增益最高的下一步核验动作
```

### 1. 拆原子主张

不要按句号机械拆。只拆会改变结论、行动或可信度的陈述。

“某论文证明新模型把幻觉率降到 0%，因此幻觉已被解决”至少包含：

1. 论文存在
2. 作者、题名和 DOI 相符
3. 被测模型存在且版本相符
4. 评测确实报告 0%
5. 0% 的指标定义与测试范围
6. 该结果可以外推到现实全部回答
7. “彻底解决”成立

若原文很长，优先审计影响最大的主张，并列出尚未审计的主张，不能静默遗漏后声称整份回答可靠。

### 2. 先让结论词可以被判定

遇到“彻底解决、准确、安全、行业第一、广泛采用、效果显著、已被证明、最新、最便宜”等会改变结论的词，先查论文方法、法规、标准或官方记录是否已经给出权威定义。没有现成定义时，再做判定条件测试：

1. 这个词具体改变了对象、指标、比较范围、时间窗口、适用场景还是行动建议？
2. 未参与生成主张的审计者能否凭同一材料和判准复现这个分类？
3. 出现什么观察结果时，这个词应被判定为不成立？

若三问答不出来，把该词标为**判准缺失**，再拆出仍可核验的较窄主张。不要直接说它一定是空话，也不要擅自替用户补一个数字门槛。若当前不存在可行的反驳条件，直接写“判准未知”，不能为了填表强造。

例：“彻底解决幻觉”至少需要定义模型版本、任务分布、错误类型、评测覆盖、观察周期和允许的失败条件。某个题集里观测到零次错误，只是一个更窄的可核验主张。

已经清楚的数字、法域、日期和对象直接放行，不为走流程而重复提问。只有一个定义差异会改变结论或行动、且现有来源无法解决时，才追问这一个阻塞性缺口；否则先审计可确定的部分并把其余标为未知。

### 3. 标记主张类型

使用最贴近的一类：

- 存在与身份
- 数字与比较
- 产品能力
- 研究发现
- 因果主张
- 法律与政策
- 引语与归属
- 预测与承诺

时效性标为高、中、低。价格、法律、职位、当前产品能力和“最新”默认高时效。

### 4. 找来源并实际打开

来源优先顺序：

1. 监管文件、法规原文、论文全文、财报、官方数据、代码和实际测试
2. 公司产品页、新闻稿、模型卡和管理层自述
3. 有方法与出处的专业二手分析
4. 普通媒体和社交媒体，只作线索
5. 另一个 AI 回答，不是证据

搜索结果摘要只用于找到页面。必须打开最终页面，记录最终 URL、来源日期、版本和访问结果。付费墙、登录、404、重定向到无关页面或抓取失败，都写“未打开”或“无法访问”。

严禁根据看起来合理的题名、作者、卷期或 DOI 补成正式引用。DOI 不解析时，只能记录当日解析失败；这不能单独证明论文永久不存在。

### 5. 判断来源角色

来源层级不等于真实性。

- 法规原文可以直接说明法规写了什么
- 论文全文可以直接说明论文报告了什么
- 公司新闻稿可以直接说明公司作了什么自述
- 公司自测不能自动升级为独立验证
- NIST 等通用框架不能自动升级为某产品认证
- 专业媒体可提供线索，核心法律、财务和产品事实仍应追到原文

每条来源标记：原始记录、主体自述、独立验证、复现测试、专业解读或线索。

### 6. 做支持范围检查

逐项对照：

- 对象：是不是同一个人、公司、模型和版本
- 时间：来源何时发布，事实核验到哪一天
- 场景：实验室、benchmark 还是现实部署
- 人群：样本是谁，能否外推到所有人
- 指标：准确率、错误率、弃答率是否被混用
- 比较：所谓最好、最低、行业第一比较了哪些候选
- 法域：国家、州、监管机构和适用对象是否一致
- 条件：缓存价、批处理价、实验设置、例外条款是否被省略

一个 benchmark 上错误率更低，只支持该模型版本、该评测和该设置。不能直接写成法律、医疗、金融等现实回答都更可靠。

### 7. 分开三道门

不要把以下三件事合并：

1. **来源身份**：论文、法规或页面是否存在，作者、版本和标识是否相符
2. **内容支持**：来源正文是否真的支持这条原子主张
3. **行动适用**：即使主张被支持，是否足以推出用户准备采取的行动

一篇真实论文可以被错误引用；一个被论文支持的群体平均结果也不必然适用于个人；一条真实法律陈述仍可能因法域、程序或个案事实不同而不能直接执行。三道门分别赋予理由，不能让前一门通过替后一门放行。

### 8. 检查推断跨度

| 级别 | 从来源走到主张需要什么 | 处理 |
|---|---|---|
| 0 | 原文直接陈述，范围一致 | 可考虑已确认 |
| 1 | 透明计算或明确术语转换 | 展示计算与条件 |
| 2 | 跨人群、时间、任务、法域、版本或比较口径 | 至多部分支持 |
| 3 | 相关性变因果、benchmark 变现实全场景、公司自述变独立事实 | 不得写来源已证实 |

研究使用 survey、self-reported、associated、predictive 或 correlates 等设计和措辞时，除非研究设计和原文明确支持因果，否则保留为相关性。不要把“批判性思考投入较少”改写成“智力下降”或“人变笨”。

因果主张还要检查：原因是否先于结果、有没有干预或可信比较、关键混杂与选择偏差如何处理、结果是否客观测量、样本能否外推。缺一项不自动判假，但不能写成因果已经被证明。

### 9. 赋予状态

只使用以下状态：

- **已确认**：已打开一手来源，直接支持，日期和范围匹配，未发现决定性冲突
- **部分支持**：来源支持更窄版本，原句含额外外推或缺少条件
- **被反驳**：可靠且可比的原始来源与主张直接冲突
- **无法核验**：来源缺失、打不开、标识无效或材料不足
- **当前未知**：事实会变化或决定性证据尚不存在，本次不能确定

找不到证据不等于被反驳。证据存在也不等于原句全部成立。

## 输出契约

默认输出简明账本。每条主张必须包含下列字段，不得省略决定性未知。

```markdown
# AI 主张审计

核验日期：YYYY-MM-DD
审计范围：已审计哪些内容；哪些内容尚未审计
快速结论：一句话，不保证绝对正确

## C1 [原子主张]
- 主张类型：
- 时效性：高 / 中 / 低
- 关键结论词与判定条件：没有则写无；判准缺失时写明缺口
- 原始来源：[标题](直接 URL)；未找到或未打开时直说
- 来源层级：A1 原始记录 / A2 主体自述 / B 专业二手 / C 线索 / D 非证据
- 证据角色：原始记录 / 主体自述 / 独立验证 / 复现测试 / 专业解读 / 线索
- 来源日期：
- 是否实际打开：是 / 否；访问结果与最终 URL
- 来源身份门：匹配 / 不匹配 / 未知
- 是否直接支持：是 / 部分 / 否
- 内容支持门：直接 / 部分 / 不支持 / 未知
- 支持范围：人群、任务、法域、时间、版本、指标、比较对象和条件
- 推断跨度：0 / 1 / 2 / 3；理由
- 行动适用门：适用 / 不足以支持行动 / 需专业确认 / 不适用
- 可反驳观察：出现什么证据会改变当前状态；无可行判准时写未知
- 反证或冲突：没有找到时也要写明
- 状态：已确认 / 部分支持 / 被反驳 / 无法核验 / 当前未知
- 置信理由：为什么给这个状态，不用百分比装精确
- 下一步核验动作：最有效的一步

## 当前未知
- 仍不能回答什么

## 最有效的下一步
1. 先做哪项核验，以及它能改变哪条状态
```

若来源很多，先列最接近原始记录且真正被打开的来源。不要用链接数量制造可信感。

输出使用最短够用的形态：非触发文本用一句话放行；单一低风险主张可把字段合并到紧凑表格；多主张、来源冲突、高时效或高风险场景使用完整账本。压缩版仍须保留最小契约的全部语义：原子主张、类型、时效性、来源与层级、来源日期、实际打开、直接支持与范围、冲突、三道门、状态、置信理由、未知和下一步。只能合并展示，不能删字段。

## 高风险边界

医疗、法律和金融结论必须同时保留：法域或适用人群、信息日期、来源版本、个案未知和专业边界。

- 医疗：不把论文或模型回答变成个体诊断、用药或停药指令
- 法律：不凭记忆确认“最新法律”，不建议在未核对法域和程序前采取不可逆行动
- 金融：不把公司自述、回测或单一指标变成收益承诺或交易指令

审计可以缩小事实争议，不能替专业人士完成个案判断。

## 迷你示例

输入：“这项 319 人调查已经证明 AI 会让人变笨。”

合格账本的核心不是换一句更柔和的话，而是记录：

- 原子主张：该调查证明 AI 导致人的客观智力下降
- 来源：打开论文全文，而非只看题名
- 支持范围：319 名知识工作者、936 个自报工作实例、横截面调查
- 是否直接支持：否；论文报告信心与自报批判性思考投入的相关性，没有测量智力下降
- 推断跨度：3，从相关性跨到因果，再跨到“变笨”
- 状态：被论文的研究设计边界反驳
- 当前未知：AI 是否造成长期客观能力下降
- 下一步：寻找随机或纵向研究，并使用客观表现指标

完整演示见 `examples/demo.md`。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 把用户给的假 DOI 排成正式引用 | 先解析 DOI 并打开出版社或论文原页 |
| 只看论文标题或摘要 | 打开正文，定位方法、结果和局限 |
| 用媒体报道确认监管事实 | 追到监管决定原文、编号、范围和生效日 |
| 把公司宣传当独立证据 | 标为主体自述，再找第三方复现或原始数据 |
| 把相关性写成因果性 | 保留研究设计与原文措辞 |
| 用旧知识回答当前价格或 CEO | 查当前官方来源并写核验日期，否则当前未知 |
| 页面打不开仍写“来源证实” | 记录访问失败和无法核验 |
| 用一个 AI 证明另一个 AI | 把第二个 AI 也当待审输入 |
| 把所有句子都事实化 | 只审计可核验外部主张 |
| “安全”“彻底解决”没有判定条件 | 先定义对象、指标、范围、时间和失败边界，再审计较窄主张 |
| 来源是真的就直接给行动建议 | 分开来源身份、内容支持与行动适用三道门 |

## 红线

- 没打开页面却写“我核验过”或“来源证实”
- 没有来源却生成像真的引用
- 用流畅度、链接数量或数字精度代替证据
- 把主体自述静默改成独立事实
- 把 benchmark 错误率等同于现实全部回答错误率
- 省略高时效主张的核验日期
- 为了满足用户的确定语气而隐藏未知
- 保证审计结果绝对正确或宣称消灭幻觉

许可与改编来源见 `NOTICE.md` 和 `PROVENANCE.md`。
