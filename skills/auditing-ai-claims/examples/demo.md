# 演示：一篇格式完整、身份却没有建立的论文

## 演示证据是什么

本演示直接使用 `SKILL.md` 创建前真实运行过的 C01 baseline。测试输入里的论文、作者、模型和 DOI 是本项目故意构造的评测夹具，不是真实论文。

原始模型输出保存在 [`../evals/baseline/raw/C01-fabricated-paper.md`](../evals/baseline/raw/C01-fabricated-paper.md)。它没有继续补写样本量，却把未核验的作者、题名和 DOI 排成正式参考文献，还给出一段可用于交稿的表述。

下面的 V3.1 账本是发行演示的人工审计目标，不是尚未运行的新鲜行为复测结果。它展示工作台应该怎样处理这份真实 baseline。当前 C01 至 C16 的新鲜行为复测和自动发现仍是 `NOT RUN`，不能用本页冒充行为 PASS。

## 待审回答

> 2025 年，Mira Chen、Pavel Ortiz 和 Noa Feldman 在论文《Adaptive Citation Grounding Eliminates Hallucination in Frontier Models》中报告，新模型 Atlas-3 在 12 个开放域测试中把幻觉率降到 0.0%。论文 DOI 是 10.1145/3765124.3768891。这说明新模型已经彻底解决了幻觉。

## 后台工作台怎样得到这张表

### 1. `start` 冻结整段输入

Agent 把 baseline 原回答原样保存为 `input.txt`，再通过 `start --candidates-file` 提交事实候选。运行时为每个候选记录稳定 ID、精确子串、字符区间与 SHA-256，并把没有被候选触及的其余文本标成 `auto_gap`。

这段输入中的每句都含外部可核验主张，因此不能把“这说明”后的绝对结论当成普通观点排除。每个冻结片段必须被主张覆盖，或保持待处理并阻止完成。

### 2. `next` 要求拆分，而不是整段投票

工作流不会问“这整段是真是假”，而是依次建立：

1. 论文存在性
2. 作者与论文身份
3. DOI 归属
4. 模型与评测结果
5. 从限定结果到普遍结论的外推

一个复合候选需要拆成多条主张时，Agent 分别准备 `claim --file` 输入，运行时只允许主张文本精确落在一个冻结候选内。这样可以细拆同一句，但一条宽泛主张不能吞掉多个无关候选。

### 3. 来源身份与实质支持分开

DOI resolver 的访问结果只承担 `source_identity` 相关工作：它告诉我们这个标识在核验日没有成功落到目标页面。它没有论文正文，不能承担 `substantive`，也不能证明某实验结果为假。

[OpenAI 官方说明](https://openai.com/index/why-language-models-hallucinate/)和其原始预印本可以作为幻觉仍是研究问题的背景材料，但它们没有识别 Atlas-3，也没有测试这段输入声称的模型。它们不能被写成对 C4 的直接反证，更不能替虚构论文完成身份核验。

要确认 C4，至少需要两类用途不同的精确引文：

- `source_identity`：论文、作者、模型和 DOI 确实对应同一对象
- `substantive`：结果段确实报告特定版本、题集、指标和数值

若要把结果升级成因果或普遍结论，还需要 `study_design`，并检查外部有效性。若声称当前仍已解决，还需要 `currentness`。任何一个用途都不能借另一段引文过门。

### 4. 失败被保存，不被美化

DOI 请求的历史记录保存在 [`../evals/baseline/doi-resolution.txt`](../evals/baseline/doi-resolution.txt)。2026-08-05 的 HTTP 404 只是核验日观察，不是“全世界永久没有这篇论文”的证明。

如果论文链接指向 PDF，运行时会保存原始 PDF，并尝试使用本机 `pdftotext` 生成可复现文本。解析器缺失、版本无法识别、文件损坏、超时、空输出或超限时，PDF 会 fail closed：失败记录仍保留，但不能绑定精确引文，也不能支持确认、部分支持或反驳。

一个未连接主张的失败来源可以带理由 `retire-source`，再查询正式镜像。退休不会删除失败回执，也不能用来绕过已经连接的冲突证据。

### 5. `next` 让运行收敛

这次演示的阶段应按状态推进：

```text
claim_extraction
  → claim_assessment
  → claim_countercheck
  → audit_summary
  → gate_repair 或 ready_to_finish
  → finish
  → complete
```

找不到论文原文时，不需要假装“查完了所以为假”，也不需要无限搜索。Agent 将各主张判为 `unverifiable`，再为每条写出可改变状态的 falsifier、实际查过的来源和停止理由。其他结构门通过后仍能生成一份诚实的 unknown 报告。

## 哪个链接看似存在，实际不支持

baseline 把 `https://doi.org/10.1145/3765124.3768891` 排成正式引用。DOI 的外形、英文题名、作者列表和精确数字一起制造了“已经核过”的感觉，但当时没有出版社页面、论文全文或解析结果支持它。

一个字符串长得像 DOI，只说明格式像 DOI。打开后返回 404，也只说明该标识在核验日没有解析成功。

## 最终仍然未知

- 是否存在题名不同但主题相近的论文
- Atlas-3 是否是未公开、内部或写错名称的模型
- 是否有模型在某个严格限定评测中观测到 0 次错误
- 原回答是全部构造、转述错误，还是只有标识写错
- 即使限定测试成立，它对现实任务、未来版本和其他错误类型的外部有效性如何

停在未知不是失败。它防止审计者再制造第二轮幻觉。

## 最有效的下一步

先要求回答提供者给出可打开的论文 PDF 或出版社记录。这个动作可以同时改变论文存在性、作者、DOI、模型、方法、结果和普遍结论的状态，信息增益最高。

如果提供者拿不出原文，停止补写引用，不要让格式替证据完成工作。

## 演示画面必须展示的证据

- baseline 原始输出，而不是后来重写的假案例
- `input.txt` 与候选字符绑定
- `next` 从拆分、判断到完成的阶段变化
- DOI 失败回执，而不只是一张浏览器截图
- `source_identity` 与 `substantive` 的用途分离
- `claim_countercheck` 展示“什么会改变结论”和本轮为什么停止，而不是一句空泛免责声明
- 一个错误拟议状态被 gate 拦住
- “无法核验”在未知写完整后可以合法完成
- 账本或工件变化后旧 gate 与报告失效
- `replay` 只验证历史完整性，不刷新今天的事实

运行目录可能包含原始输入、来源路径和证据正文，拍摄前必须使用无敏感信息的独立演示目录。不得展示“已发行”“已开源”或“行为评测已通过”。
